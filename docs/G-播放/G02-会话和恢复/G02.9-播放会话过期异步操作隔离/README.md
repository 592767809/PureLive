# G02.9 播放会话过期异步操作隔离

- 状态以[登记表](../../../tasks.toml)为准。
- 来源：播放恢复与会话切换代码审查。
- 关联：[G02.3](../G02.3-断网不提示重连且不自己接上/README.md)、[G02.8](../G02.8-正式包缓冲停滞状态诊断/README.md)，issues/33、issues/49。

## 目标与边界

只修复当前会话状态机中能确定性复现的错误排空和生命周期隔离缺陷，保留现有恢复预算、线路选择、解码策略、暂停与手动重试语义。此项不是两台电视原问题根因的完整证明，不关闭 #33/#49。

## 现状与方案

1. `PlaybackSession._retryRound` 在刷新处理了错误时提前返回，可能跳过刷新后的打开失败所留下的 `_pendingError`；需要完整排空而不是让状态长期停在缓冲。
2. `stop` 等待旧输入关闭后读取可变 `_engine`，有机会停止较新的房间；等待之后先检查会话所有权。
3. `_openSource` 的超时回调读取可变 `_transport`，旧请求的期限有机会取消较新的打开；超时只处理属于该请求的资源。
4. 画面停滞恢复等待旧输入关闭后直接释放共享引擎，同样可能碰到新会话；恢复后的释放也须检查代次。

3.x 的播放/停止/重连操作习惯继续保留；本次不借用上游实现或更换内核，不改变可见功能。现有 5.x 会话测试是本次有界修正的直接行为基线。
