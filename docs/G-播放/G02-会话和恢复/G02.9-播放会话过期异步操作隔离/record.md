# G02.9 记录

## 根因与修复

1. 重试轮刷新成功后，引擎打开失败所留下的待处理错误可能被提前返回跳过。修复后保持既有预算，继续排空错误；旧轮次不能取走新会话的错误。
2. 旧停止等待输入释放后可能访问新会话的共享引擎。释放结束后先核对会话代次。
3. 旧打开超时可能取消新打开，且同一个 transport 可以被复用。期限回调同时使用捕获的 transport 和 source fence 代次；无源新请求没有开启新输入时，仍清理旧待用资源。
4. 画面停滞恢复等待旧输入释放后可能释放新会话引擎。触及共享引擎前重新核对会话代次。

## 回归证据

- 修改前：同一组 50 项会话测试中 44 通过、6 项行为断言失败；分别覆盖错误排空、两类打开期限交错、两类迟到停止交错及迟到引擎释放。
- 修改后：相同 50 项全部通过。新增旧重试错误所有权用例后，会话测试 51/51、播放包 95/95 通过。
- 变异验证：仅移除旧重试的会话所有权保护，新会话刷新次数由预期 2 变成 1；恢复保护后通过。
- 可控释放屏障保证新房间已播放再放行旧清理；同时检查真实引擎调用和释放标记，不只检查会话状态。
- 独立代码与回归审查未发现阻断意见。
