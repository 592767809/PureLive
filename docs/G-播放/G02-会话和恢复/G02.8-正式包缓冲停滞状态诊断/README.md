# G02.8 正式包缓冲停滞状态诊断

#33 和 #49 的现有日志有缓冲超时，但无法区分原生内核是否空闲、缓存是否有数据、播放时间是否前进、音视频参数是否出现。`MpvEngine._watchBuffering` 以前直接跳过 release；反复发出的 buffering=true 还会重置三秒探测期限。

正式包沿用本地日志通道，每次持续缓冲仅发出一次 `mpv-buffering` 快照；只读取固定列表中的布尔值、数值，不读取媒体地址、HTTP 头、Cookie、账号或原生日志原文。各查询一秒超时，换源、缓冲解除、停止和销毁使在途结果失效。该探测不修改播放状态或恢复策略。

这不是 #33/#49 的根因修复承诺。视频参数和既有 timing 日志也不是物理屏幕已经呈现图像的证明；原机换房、音画同步和网络条件仍须分别核验。
