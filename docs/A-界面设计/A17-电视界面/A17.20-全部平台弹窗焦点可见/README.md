# A17.20 全部平台弹窗焦点可见

来源：[#74](https://github.com/wzgrx/PureLive/issues/74)。用户明确要求热门页的“全部平台”弹窗每次打开聚焦第一项；这项要求替代 A17.3 的“打开聚焦当前平台”，不改变普通设置选择框的当前项规则。

## 根因

- `tv_popular_pane.dart` 的平台按钮用 `id == _current` 自动聚焦，当前平台在最后几行时，弹窗初始滚动位置仍在顶部。
- `TvFocusable` 保留按钮 1.05 倍放大和 3 画布像素外描边；原弹窗只给滚动视口预留 6 像素。按钮的横向放大量取决于宽度，6 像素不足以容纳侧边完整描边。
- Flutter 的方向键遍历已有布局可见性处理，但布局边界不包含放大和外描边；不能把这一点表述为方向键完全不会滚动。
- 旧 `tv_browse_test.dart` 主动调用 `tester.ensureVisible(last)` 再触摸最后一项，没有覆盖遥控器初始焦点和完整绘制边界。

## 最小方案

保持三列、顺序、文字、选中填充和按钮样式。第一项每次获得初始焦点，已选平台仍只以选中填充表示。弹窗中的私有网格拥有独立滚动控制器，获焦后只把该按钮在自己的纵向视口中居中，不滚动背后的平台标签。左右留白按单元格最大宽度、放大量及外描边计算，上下留白兼顾字号。关闭后销毁控制器，过期的帧回调检查挂载状态和当前焦点。

`TvButton.onFocusChange` 仅转发已有 `TvFocusable.onFocusChange`，不改共享焦点规则。确认仍切换平台并关闭，返回和“关闭”不改变选择，路由焦点恢复到“全部平台”。

## 验证边界

定向测试覆盖每次打开、改变选择、返回、关闭、四向逐项遍历、上下滚动、整圈几何和像素、720p 字号提升以及矮窗口；只使用离线服务。测试结果另见记录，未执行的检查不计为通过。自动化回归不是 Sony 或其他电视真机验收。
