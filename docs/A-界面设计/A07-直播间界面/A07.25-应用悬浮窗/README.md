# A07.25 应用悬浮窗

- 编号、状态、档位、规模：以登记表为准，见[子分类页](../README.md)和 [STATUS.md](../../../STATUS.md)
- 类型：功能
- 来源：用户 2026-10-17：“做应用自己画的悬浮窗”“画中画保留，+做应用自己画的悬浮窗（应用自己画的小窗，借‘显示在其他应用的上层’这个权限，离开应用后继续悬浮在其他应用上面，而不是换成系统画中画），用户可以自己选择”“必要的权限需要，可以设计，用户自己选择打开就行”
- 相关：A07.8、A07.24（应用内小窗、画中画）；D-042

## 做法

- 2026-10-17 第二版（用户：“点击右上角小窗图标，后续都显示应用悬浮窗的小窗，默认使用这个，画中画设计成第二个选择，用户自己打开开关选择就行”）：
  - 小窗默认就是应用悬浮窗：直播间画面上的小窗按钮、应用内小窗的“小窗”按钮、离开应用时自动小窗，都用它。
  - 设置 → 视频 → 小窗：“离开应用时自动小窗”（原“离开应用时自动画中画”，键 `autoPipOnLeave`，默认关，和以前一样）、“小窗用系统画中画”（新键 `useSystemPip`，默认关；打开后上面三处都用系统画中画）、“悬浮窗权限”（显示开没开，点了去系统设置）。
  - 以前打开过“离开应用时自动画中画”的用户，第一次启动时 `useSystemPip` 记成开，照旧用画中画（`keepPictureInPicture`）。
  - 没有“显示在其他应用的上层”权限时，点小窗按钮出提示“小窗需要‘显示在其他应用的上层’权限”和“去开启权限”，不退到后台；自动小窗什么也不出。
- 第一版是“离开应用后”三选一（不保留画面 / 系统画中画 / 应用悬浮窗），没发布就换成了上面的做法。
- 小窗按钮：应用退到后台，悬浮窗出在右下角（应用内小窗的大小）；从应用内小窗点：出在小窗原来的位置。
- 悬浮窗就是应用内小窗：同一套按钮（回到直播间、关闭、暂停 / 播放、静音、弹幕开关）、小窗弹幕、录制标记；拖动画面移动窗口，拖角上的把手无级改大小；系统画中画的按钮不出现。
- 实现：应用唯一的 Flutter 引擎（audio_service 保管，比 Activity 活得久）离开应用时从 Activity 的画面挪到一个 `TYPE_APPLICATION_OVERLAY` 窗口里的小 `FlutterView`，回来时挪回去，所以播放器、画面、弹幕都不重建（`FloatingOverlay.kt`，通道 `pure_live/overlay`）。悬浮窗显示时不向 Dart 报告应用退到后台（它确实在屏幕上）。拖动和改大小按手指在屏幕上的坐标由原生跟随（窗口在手指下移动，Flutter 自己的坐标会跟着变）。
- iOS 没有这个（系统不允许），选项只有前两个。
