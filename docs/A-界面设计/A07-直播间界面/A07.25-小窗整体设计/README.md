## 结论

只做**一个**小窗：应用里和应用外是同一个窗口、同一个播放器。样子和手势以 5.4.1 为底，只改用户指出过的问题：

- 把手固定在右下角、弹幕开关和画中画固定在左下角，不再左右换边；
- 能拖到屏幕最上和最下；
- 收边拉回来不触发返回；
- 位置跨重启记住；
- 点小窗按钮不再退到桌面；
- 开了悬浮窗权限后，离开应用小窗留在其他应用上面；
- 系统画中画改成第二选择，用开关打开。

代码先恢复成 5.4.1（`279c5108d`，撤回了 `bd4096bf9`、`d61091778`、`df14cc2f6`、`9607ca110`），出了第 1 版设计（`a13fd020d`）。用户定了 J1（把手右下角，弹幕开关和画中画左下角），其余按建议；又要求把动画设计好（M1～M12）。第 2 版按此实现，见“结果”。

## 设计原则

1. **只有一个小窗。**应用里和应用外是同一个窗口、同一个播放器，进出不重建、不断流，按钮和手势完全一样。
2. **以 5.4.1 为底。**用户说过好的（按钮位置、收边、无级缩放）不动，只改用户指出的问题。
3. **不打断。**点小窗按钮不会退到桌面；离开应用时小窗跟着出去，回来时回到原处。
4. **用户说了算。**大小无级、位置随意，都跨重启记住；权限只在用户自己选的时候才去开；画中画是可选的第二种。
5. **不和系统手势打架。**拖动的起点都在返回手势区外面。
6. **先出完整设计，定了再做。**一块一块做完，K90 上看过再推。

## 动画

都用应用已有的同一根弹簧（`AppMotion.floatingSpring`：质量 1、刚度 500、临界阻尼，约 0.3 秒），带着手指的速度；系统“移除动画”开着时全部直接到位。动画中只移动和缩放画出来的样子，播放器、弹幕不重建（每一帧都是同一组组件，不动时等于没有）。

| 编号 | 什么时候 | 怎么动 | 参数 |
|---|---|---|---|
| M1 | 点小窗按钮、返回离开直播间 | 画面从直播间里的位置直接飞到小窗的位置，一路缩小；直播间页面在下面照常退出 | 弹簧；直播间一开始退出就交给小窗（等页面退完再出现，画面会在原处闪回来） |
| M2 | 点“回到直播间” | 稍放大到 1.04 倍并淡出，再打开直播间 | 0.12 秒 |
| M3 | 点 ✕ | 缩到 0.85 倍并淡出，再停止播放 | 0.18 秒 |
| M4 | 拖动松手 | 带着手指速度滑到近的一边，到了就停（照 A03.4） | 弹簧 |
| M5 | 收边、拉回 | 同 M4；收好后竖条把手淡入 | 把手 0.15 秒 |
| M6 | 拉把手、两指缩放 | 跟手，没有动画 | — |

## 定下来的

- J1 把手放哪：用户 2026-10-18 定为**把手固定右下角，弹幕开关和画中画固定左下角，以后不换边**（第 1 版建议的左下角和 5.4.1 的换边都不采用）。
- J2 没开悬浮窗权限时离开应用：A，小窗先藏起来，回来还在；第一次回来提示一次“去开启”（用户：“其他看你设计”）。
- J3 收边：A，保留并按 c5 改。
- J4 重开应用后的位置：A，回到上次那一边、那个高度，收着的不再收着。

## 不做的和原因

- 双击切换大小（安卓画中画的做法）：双击回直播间是 5.4.1 的习惯。
- 往下甩关闭：和拖动冲突，已经有 ✕。
- 四边四角都能拉（上游）：220 宽的小窗边太窄，和拖动、按钮打架。
- 只在靠近边时才贴边（上游）：5.4.1 松手贴近的一边，用户没提过意见。
- 点小窗按钮直接退到桌面（上一版）：去掉。
- iOS 悬浮窗：系统不允许。

## 拿不准的地方

1. 小米 HyperOS 可能清掉“只剩悬浮窗在跑”的应用：K90 上挂 30 分钟看；被清的话在设置里说明去开“无限制”后台。
2. 有的系统有“后台弹出界面”权限，可能挡住从悬浮窗点“回到直播间”打开应用：K90 上验证，挡住的话提示去开。
3. 返回手势区宽度各家不同，用户也能调：收边那条按 56 设计，K90 上实测。
4. 排除返回手势最多 200 高：竖屏直播的小窗比这高，只排除把手附近的 200。
5. 锁屏时悬浮窗里的播放照“后台播放”的设置。

## 结果

- 应用里（c2～c7、c13、M1～M8）：`apps/pure_live/lib/features/live_play/mini/floating_window.dart`（收边露出和把手、手势排除、位置跨重启、从画面飞进、关闭和回直播间的淡出、自己挪位置的滑动、从桌面回来接上位置和大小）、`mini/mini_player.dart`（把手的样子和位置、告诉小窗按钮是否显示）、`logic/mini_window.dart`（把手往中间或往下变大、露出宽度、排除范围、重启后不收着）、`live_play_page.dart`（小窗按钮缩成小窗、一开始退出就交给小窗）、`mini/room_mini_window.dart`（小窗按钮、一次性提示）。
- 应用外（c8～c12、M10）：`android/.../FloatingOverlay.kt`（同一个引擎挪到悬浮窗；松手贴边、甩进边收起、点露出的那条拉回、把手、两指缩放、排除返回手势、离开时把位置和大小交回应用），`lib/platform/overlay_window.dart`。
- 设置：键 `autoPipOnLeave`（文字改成“离开应用时自动小窗”）、新键 `useSystemPip`（老用户开过自动画中画的升级时自动打开，`keepPictureInPicture`）、`floatWindowPosition`、`floatOverlayTipShown`（内部）；15 种语言。
- 撤回前的实现（`bd4096bf9` 等）里验证过的部分照用，和这版设计不同的地方都改掉了：小窗按钮不再退到桌面，悬浮窗跟出去不再看“自动小窗”开关，小窗上的画中画按钮只开系统画中画，把手和按钮按 J1。
- 测试和真机见 [record.md](record.md)、[verify.md](verify.md)。
