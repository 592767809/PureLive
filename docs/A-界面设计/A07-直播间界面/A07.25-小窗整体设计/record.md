## 做法

- 撤回前的代码（`279c5108d..6b014f7b5`，不含文档）先整体放回，再逐条改成这版设计：
  - 小窗按钮：不再 `enterNow`（退到桌面再出悬浮窗），改成直播间页面关进应用内小窗（`RoomMiniWindow.shrinkToMini`）；原生 `enterNow` 删掉。
  - 离开应用：小窗开着时按 `miniWindowKind`（悬浮窗或系统画中画）布防，不再看“离开应用时自动小窗”；直播间页面离开应用仍看这个开关（`leaveAppWindow`）。
  - 小窗上的画中画按钮只开系统画中画。
  - 把手：一直在右下角（`_GripPainter` 画四分之一圆和直角线）；方向 `MiniGripCorner` 只表示往哪边长；`inAppMiniGripExtent` 加上“往下拉更多时也变大”。
  - 收边：露出 `inAppMiniPeekFor(gestureInset, width)` = 宽的 1/5、至少 56、比返回手势区多 32；把手竖条 `_TuckHandle`；排除范围 `inAppMiniExclusion`（中间最多 200 高）。
  - 重启后的位置：收着的放回那一边不收着（`inAppMiniUntucked`）。
  - 没权限的一次性提示 `OverlayTip`（新内部设置 `floatOverlayTipShown`）。
- 动画：
  - M1、M8 用一个 `_morph` 控制器（`AnimationController.unbounded` + `SpringSimulation(AppMotion.floatingSpring)`），窗口按目标位置布局，只用 `Transform` 画在途中；M2、M3 用 `_exit` 控制器，`Opacity` + `Transform.scale`。这几层一直在组件树里（不动时等于没有），否则组件树变了，里面的播放器、弹幕、按钮会被重建（第一次写成“动画时才包一层”，测试里按钮计时和弹幕全被重置）。
  - M1 的交接时机：原来房间在直播间页面销毁时（退场动画结束后）才交给小窗，小窗会在页面已经滑走后从画面原处突然出现。改成页面一开始关闭（`onPopInvokedWithResult` 之后一帧，或点小窗按钮当时）就交给小窗，`_handedOver` 标记让 `dispose` 不再处理这个房间。
  - M8 只在“不是手指挪的”位置变化时触发：拖动、松手滑动、改大小结束、从桌面回来时把“上一帧的位置”清掉，避免弹簧最后一帧和目标差一点又滑一次。
- 原生 `FloatingOverlay.kt` 补齐和应用里一样的手感：松手按 `inAppMiniSettle` 的规则贴边或收边（临界阻尼弹簧，带手指速度，到了就停）、点露出的那条拉回、把手往中间或往下变大、两指缩放（Dart 传比例）、收边那条和按钮显示时的把手排除返回手势、窗口离开时把位置和大小（`placed`）交回 Dart。

## K90 上发现并改掉的

1. 小窗贴着屏幕右边时，拉右下角的把手会触发系统返回，应用退到桌面。改成按钮显示时把手那一角排除返回手势（应用里用 `SystemGestureExclusion`，悬浮窗里原生 `excludeGrip`）。
2. 甩进边收起后，从把手往回拉偶尔拉不动，点它反而出按钮。根因：拖动一开始窗口就不算收起，接住这次拖动的手势层被移出组件树，拖动结束收不到，窗口一直是“拖动中”。改成这次拖动没结束前手势层一直留着（`_pullingOut`）。
3. 回桌面时悬浮窗的位置是松手滑动途中的位置。改成滑动停稳后再布防一次。
4. 从桌面回到应用，位置接上了，大小却回到默认：换算大小时窗口还铺满悬浮窗那块地方，按那块的尺寸限制了大小。改成回到应用、按应用的尺寸布局后再换算（`_takePlaced`）。
5. 测试里：`_syncAutoPipLater`、`_syncExclusionLater` 只注册了帧后回调，没要求一帧，权限变化这种不重画的变化就不同步。改成同时 `ensureVisualUpdate`。
