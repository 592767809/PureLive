# A13.5 沉浸和全屏直接换台

来源：[#43 的明确补充](https://github.com/wzgrx/PureLive/issues/43#issuecomment-6384805621)。反馈者已经找到换台图标，希望与普通模式一样在音量调节下方直接选台。维护者本轮要求解决、发布、合并并关闭已修复报告；按 D-003 选择复用现有组件的最小方案。

## 对照与设计

3.x 将选台作为格子菜单动作；本仓库普通宽屏模式已由 `_controlsAndPicker` 在音量下方显示同一 `MultiviewRoomPicker`。沉浸／全屏的 `_Overlay.cell` 却只显示滚动控制栏，必须再点图标才能进入单独列表。这是本次明确的可发现性与操作步骤差异。

横向侧栏和宽屏布局中的格子面板复用普通模式的控制栏、分隔线、目标提示、搜索、关注／历史与列表，放在音量下方。右键／长按时固定该格为替换目标，即使其他格仍为空也不得填错格；选台后关闭浮层并保留当前显示模式。点已播放房间继续选择现有格，避免重复解码。其他格会话与音量保留，原换台图标与 Esc／返回链保留。

竖屏紧凑手机仍保留原紧凑底部控制面板和图标入口；宽屏竖向窗口使用有足够高度的底部组合面板。短侧栏／大字时为控制区限制最大高度并允许滚动，列表沿用既有自适应滚动，全部入口可达。没有新文字、图标、设置或播放器策略。

界面清点：普通宽屏控制与列表为基线；沉浸与全屏侧栏、宽屏竖向底部面板、短窗口／大字为改动形态；紧凑竖屏为保留形态。空、离线、错误、播放中、已播放房间及关注／历史／搜索复用现有状态。按 PROCESS 小任务规则，采用实际组件回归图作前后对照，独立原生结果另记，不发布 Claude 私有评审页。

## 验证计划

先保留旧实现缺少直接列表的失败回归；覆盖两个显示模式、深浅主题、空余格仍替换右键格、已播房间不重复、其他会话保留、Esc 链、短窗口和大字。图像只作为合成布局证据；Windows 隔离候选需实际右键换台验证。完整 all/14 通过后构建发布，不将首页启动等同多路长期播放。


## 实现及冻结前结果

生产范围仅 `multiview_page.dart`、`widgets/cell_controls.dart` 以及发布版本。浮层使用同一 `_controlsAndPicker`；显式使用当前面板格作为选台目标，避免沿用其他空格或旧目标。短侧栏控制区最多占内容高度一半并可滚动，列表使用原自适应滚动；选择后只关闭浮层，原显示模式、其他格会话和重复房间规则保留。宽屏竖向窗口组合面板使用既有选台面板高度，紧凑竖屏仍为原控制面板。

大字截图暴露固定 40 宽音量百分比换行；补充真实高度回归在旧宽度失败。侧栏按当前字体与文本缩放测量最大 `100%` 的宽度，数字保持一行；普通手机横排宽度预算保留，不缩小文字。

旧实现六项定向回归均因直接列表不存在失败；修正后六项通过，包含 2 倍系统文字。完整多画面 46 项曾通过；随后增加的百分比几何回归与最终六项截图运行通过，完整仓库检查接着执行。第一次扩展运行中的两个失败均保留：标题 finder 同时匹配了新列表已有房间徽标，导致后续方向恢复用例受未完成清理影响；将断言限定在真实面板标题后全部 46 项通过，方向逻辑未改。

截图辅助为合成评审单独注册文泉驿 `PureLiveQaCjk`，只在 PURELIVE_QA_DIR／FONT 均启用时设置测试主题字体；正常测试与发布字体不变。早期占位字形帧保留在本地，不作为文字审查证据。最终六张和一张改前图已逐张查看：正常侧栏列表紧随音量，深浅文字可读；大字百分比为单行，短面板可滚动选到房间，竖向窗口不溢出。全部是假房间与假播放器，不是真机或真实直播截图。
