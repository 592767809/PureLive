# D02.3 正则探测调度延迟误判修复

接 D02.2。旧 `_slow` 对单次超过20ms的wall-clock样本直接拒绝，即使后续匹配只需很短时间；两次短暂调度暂停也会把正常 `/加.*群/` 判为tooSlow。首轮全仓库门禁暴露此类失败，单独重跑不能作为修复。

保留2ms预算、输入长度上限和嵌套重复静态拒绝。在首次超预算的同一输入上最多再测两次，只在三次都超预算时拒绝，不继续扩大慢输入。测量入口可注入时间，校准和测试不用依赖主机当时是否被抢占。

旧逻辑下30ms后恢复、连续两次3ms后恢复都会误拒，修改前实际模块回归失败；修正后应接受，连续三次超预算仍拒绝。真实高复杂度模式仍由原有回归验证在短时间内拒绝。
