# Y01.26 5.4.15全平台发布（构建号5119）：电视菜单与IPTV

来源：[#46](https://github.com/wzgrx/PureLive/issues/46)。

在独立工作区基于5.4.14处理本轮反馈。先以受控测试确认旧实现失败，再做最小修正；只使用假请求、固定节目和测试数据，真实媒体另作匿名只读检查。电视菜单保留既有放大与外描边，给绘制留出边缘；节目单应响应详情、控制器和所选源变化，隔离迟到结果，避免每帧重新读取。RTP只补全导入和读取协议，不将解析成功写成原电视组播播放验收。

允许目录：tv/home及对应测试、features/live_play/dialogs/iptv_guide.dart及对应测试、packages/live_iptv协议解析及测试、本任务文档及发布所需版本和说明。iOS与Windows、快手电视另根据证据评估，未确认根因不盲改播放策略。保留正式安装、用户数据、登录凭据；手机只操作已授权v4dev。完整all/14通过后同提交构建十包，核对十一项远端哈希及各端启动，再合并发布、同步更新JSON和关闭已解决反馈。旧库未来例外不得继承D-056；如仍失败，应完成候选校验后单独请求本版授权。

实现、回归和原生结果随后逐条记录，当前未发布。


## 冻结前实现与检查

电视根因：滚动内容自身不裁剪，但外层 _VerticalClip 从y=0开始截断，首项放大后的外描边位于视口上方。修正保留垂直裁剪，为视口上下各预留8个随文字缩放的画布像素，并只允许焦点画面绘入该预留带；不取消全局裁剪、不改变TvFocusable卡片规则。有效像素回归经方向键实际触发焦点后，在旧代码准确失败，修正后首／末项、放大开／关四项通过。最初只采选中态而无真实焦点的像素断言不作为缺陷证据，日志单独保留。改前及最终四帧已逐张查看，全部使用假数据和测试字体，不是真机图。

节目单根因：initState仅读取一次，房间通知只重建显示，不重新读取；didUpdateWidget也仅更换reveal监听。现监听房间ID、epgId、回看天数及选中节目源，换控制器时重绑监听并加载，递增请求代数隔离迟到结果；无关标题/聊天通知不读数据。空列表或失败时的reveal可重试，加载中只定位而不排队；销毁取消源监听并使旧请求失效。六项受控异步回归覆盖详情晚到、改源、换控制器、清空源后迟到结果、无关通知和空列表重试。

RTP根因：M3U/TXT两处协议集合遗漏rtp，IptvSite读取直接URL时复用它们。只补充两集合；三项改前失败的M3U、TXT导入到存储/房间/输入及直接RTP房间读取检查已通过，HTTP等原协议保持。解析测试不访问组播网络，不将其写成原网络播放验收。

iPhone #41在5.4.14仍无提示，完整播放界面横屏安全区内左右滑动的两项模拟原生通道检查通过，尚未复现原机。新增iOS固定阶段日志及首次更新限频回归；原18项延迟回读逻辑保持，未改手势判定和原生音量接口。#41/#49已回复取证，#33/#42/#47保持开放。Windows上游有相似呈现问题报告，但无原机错误码，不能直接认定本例根因。

相关包与房间/电视/手势回归101项通过，应用静态分析无问题。四条样式提示修正后再检查；没有将静态失败轮次写成通过。接下来完整all/14、同源十包与原生验收，结果分别补齐；当前未公开5.4.15。


## 第三候选接续

第二候选 Linux RTP 通过，但 Android 原生检测发现缺少 rtp/sdp 解复用器，已否决且保留全部十包。之前 opaque RTP 方案及其通过记录仅代表该候选和对应环境，不是最终方案。最终保持 RTP URL，按每次 open 选择 MPEG-TS 并对其他协议清空覆盖；已撤回 media_kit 的 RTP 修改。正常 K90 应用依次 RTP→HTTP MP4→RTP 验证、最终完整门禁与全部十包必须重新执行。详见 G02.6。本轮同时审查合入 PR #51，修正混合备份保留顺序、目录边界及隐藏窗口调度，默认仍关闭且不含账号；未验证的 Apple/电视场景保持待真机。


## 第三候选首帧否决与第四候选

第三候选在完整门禁和Linux原生通过后，最终K90包仍出现首帧前 video_decoder_runtime 两次、2.9秒即终止恢复，实际画面后来仍变化的错误遮罩。已否决，相关APK哈希、Info日志及离线复现保留。G02.7只给RTP首次输出前可恢复解码诊断增加有界等待；最终普通包必须多次冷启动、重载与协议切换，并逐对检查画面和本次日志，不能沿用第三候选预检作为最终验收。临时本地日志开关最终恢复原关/Info。


## 5.4.15 发布交付

[5.4.15](https://github.com/wzgrx/PureLive/releases/tag/v5.4.15) 已公开，PR #50 合并 `7974b0338dcb408949c73d7920d0c3a3934f6114`；构建与标签固定 `91a8cf04cda23a9718368c77122a5553a48a9f72`。最终源码完整 all/14 通过，十个正式包和 SHA256SUMS 共十一项远端 SHA-256 匹配，匿名下载与校验文件内容检查通过。首轮因既有 Socket 测试固定等待失败，受控事件循环延迟复现后改为有上限的完成条件等待及失败清理，生产网络源码未改；首轮失败回执保留，未靠重跑豁免。

电视代理页关闭代理时，禁用编辑区排除方向焦点；旧候选C4的Windows电视模式用实际Down复现白框消失，旧源码两项失败回归保留，最小修正后焦点及既有设置17项通过。最终正式Windows包的电视模式再用实际方向键检查两个开关白框、下移和返回；#52按共享修正发布关闭，原Sony和软键盘仍有现场边界。C4源码all14和正常RTP预检通过，因新反馈扩充而作废发布候选，六个本地包与私有草稿保留，Apple原始产物有平台保留期限，具体到期时间另记；C5重跑完整门禁和同提交十包，不混用旧包。

电视菜单保留放大和描边，在滚动视口首尾留出绘制空间。旧实际焦点截图上沿裁切已复现；新四项像素检查覆盖首末项及放大开关，逐张检查。K90 同源 v4dev 保留数据安装并核对 APK 哈希，在电视模式实际查看首末项焦点，随后恢复原界面模式和精确旋转状态。原 Sony Android9 及不同遥控器没有直接操作；#46 按已验证的绘制修复发布回复关闭。

节目单覆盖晚到详情、源变化、换台、控制器重绑、迟到旧结果与空列表重试；无关房间通知不触发读取，加载中不排队。RTP 覆盖 M3U/TXT 导入至频道和播放地址读取，旧协议拒绝已复现。隔离 Windows 正式候选首次进入即显示生成的本地节目单，无需进出全屏；Linux 正式候选实际接收本地 HTTP 与 RTP MPEG-TS 变化画面并显示节目单；K90 最终普通应用已分别冷启动核对 RTP MPEG-TS 与 MP4 的变化画面；不把同地址界面刷新当成原生重新打开，同一播放器协议切换不计入原生验收，容器覆盖清空另由输入协调回归检查。全部媒体和频道均为生成的无凭据夹具，静音测试不证明听感，回环接收不代替运营商组播网络、网卡和路由验收。#48 按两项修复发布回复关闭。

iPhone 仅增加固定阶段且每次拖动首次更新限频的手势日志，不记录坐标、原生音量亮度值、媒体或账号信息。完整房间及模拟原生通道回归通过，不等同于原 iPhone15ProMax 手势无提示已修复。#41最新录屏已查看，前段闭锁、后段解锁和完整控制条可见，查看画面未见百分比提示；缺少触点轨迹，不能只按锁定归因，也不能据此认定原生接口失败，已请正式版本发布后补充一次有限阶段日志。#33/#41/#42/#47/#49 继续按各自证据开放；Windows/GTX760 偶发整窗白屏与快手 Sony 电视播放没有因其他环境正常而关闭。

最新反馈单独核对并回复：#42是不同系统的两台设备，自签全能签/LC与TrollStore结果不同，不能当成同设备签名对照；#33部分抖音配置颜色正常，但另一个房间详情NotFound与进入playing后缓冲超时分属不同阶段，其他平台故障继续取证。#49后续兼容关闭时硬解开/关均黑屏无声，重启清缓存无效，日志中缓冲超时与更早的RiskControl分开判断；开发机分别读取Sky_LoveFree和xye-0901的FLV前缀成功，仅用于取流对照。原机随后补充电信网络曾成功一次，移动热点下cchnb1205两次成功、换AK0212005失败后回原房也失败，日志两次playing约2.1秒后另有缓冲超时；两种网络均有成功和失败，不能仅归因路由器，已将后续对照收敛到固定网络的换房、会话清理和失败恢复，不把猜测当结论。原Sony解码、音频及这条换房故障仍未验收，反馈继续开放。

Windows 与 Linux 测试实际二进制均核对到正式归档，测试数据库和额外实例独立，正式安装、用户数据和开机启动项未操作。Apple 首页与系统分享提示逐张检查，分享确认未接受；两个独立 macOS 作业原样解开同一最终 ZIP，各两次启动及 5/30/90 秒、菜单调用和关窗重开共24帧检查，四次为 Skia Metal，未见已知 GPU Hang 签名。该结果只覆盖所测云端环境。iOS/macOS 原生内核各执行一秒 PCM→WAV，独立核对头和内容，不能作为 #42 原自签设备直播录制与导出验收。安装覆盖、Apple 真机和长期播放仍有范围限制。


WebDAV 自动备份经 PR #51 合并审查后进入同一最终源码，默认关闭、24 小时、purelive 目录、保留 7 份、不含账号。隔离Windows最终正式包的实际自动备份弹窗已逐项核对这些默认值，并查看未选服务器提示，取消后未保存或向真实服务器上传。混合备份类型按时间保留、仅清理配置目录直接子自动文件、运行中和启动时隐藏窗口暂停检查四项旧代码失败回归已修正，相关服务及界面55项通过。已开始的上传可继续完成，后台不启动新检查；不自动恢复。原供应商服务器及Apple/电视等未逐项验证场景保留待真机，不用本地服务测试代替。

第二候选虽然 Linux 成功，但 Android 精确内核缺少 rtp/sdp 解复用器，已否决并保留其全部包和远端私有草稿。最终撤回 media_kit 的 RTP 专用修改，使用原 RTP URI 与逐次 MPEG-TS 容器选择/清空。第三候选另发现首帧前过早耗尽解码恢复，虽有变化画面仍显示解码失败，已再次否决。G02.7给RTP首次输出前非致命解码诊断5秒有界等待，默认其他协议、运行期及致命错误保持原规则。第四候选预构建源码指纹与该候选后续完整门禁指纹一致，正常应用的三次独立RTP冷启动和一次MP4冷启动同时检查变化画面、本次Info日志与无失败覆盖层；同房间刷新按钮已实际操作，但相同地址没有新增原生open计时，因此仅认定界面刷新，不能声称解码器重开已验证。叠加打开多个相同接收端点的早期脚本结果已拒绝。因#52扩充到第五候选后各平台再次重新构建，没有混用前四轮资产；最终普通profile包另外绑定安装哈希和原生验证回执。临时仅v4dev开启的本地日志最终恢复原关/Info。
