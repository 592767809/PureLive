# Y02.2 更新源一致性与防降级

- 接 Y02.1；来源：[GitHub issue #70](https://github.com/wzgrx/PureLive/issues/70)。
- 范围：更新检查、版本/包身份绑定、过期检查隔离、更新入口防降级。电视外壳样式、下载字节校验和原设备验收不在本批修复结论内。

## 根因与 3.x 对照

3.x 和原来的 5.x 都分别赛跑 `version.json` 与 `releases.json`，最快响应可能来自不同缓存代际。`UpdateInfo.newerThan` 已正确区分 5.4.17 与 5.4.18，不是比较器把旧版本算新；问题在于旧元数据仍被显示为“最新”且提供安装入口。历史资产只按版本名关联，未检查构建号。版本页还在 mounted/generation 检查之前写全局更新角标。

3.x `VersionUtil` 和 `ReleaseModel` 的原格式继续保留：两个 JSON 的位置、根结构、字段、平台块不改。本批不改任何发布文件、版本号或设置键。历史版本的主动下载及确认保持独立，不冒充推荐更新。

## 实现规则

1. 每个版本响应先解析有效数字版本与正整数构建号；等所有响应结束或原有 10 秒期限，取已观察到的最高版本/构建，并取消剩余请求。损坏响应不能抢先取消正常响应。
2. 有新版本时，历史请求仍有 15 秒上限；只接受包含相同版本和构建、当前平台可用安装包的结果；Android 要齐全提供元数据声明的 ABI。空、坏、旧历史不抢占正确结果。两个阶段总上限仍为原来的 25 秒；代价是不会仅因第一个旧响应而立刻结束检查。
3. 当前发布各平台均使用 `PureLive-<version>-<build>-...` 文件名；校验该身份及 HTTPS URL 的文件名一致性。5.4.18 的十个 Android、Windows、Linux、macOS、iOS 安装包已逐项核对。不明确的旧文件仍可在版本历史/发布页主动下载，不能被当成新版本安装包。
4. 版本与匹配文件组成不可变快照，一次提交到页面；mounted/generation 检查后才能更新角标。刷新期间旧快照不响应点击/焦点操作。
5. 不接受比已安装版本低的结果；正常升级还要求构建号严格大于已安装构建，即使版本名变大也不能回退或复用构建号（PROCESS 第 11 节）。数字版本比较器保持原义，安装资格单独判断。当前构建不显示“升级安装”；可到发布页重新下载。再次检查失败或只收到更旧元数据时，保留内存里已验证身份的上次快照，明确写“上次检查结果”，不声称最新。应用重启不保留缓存。
6. 进入应用内更新下载前，再检查升级资格（含构建号递增）、文件身份与下载源属于该文件。版本历史的明确确认通过单独的历史意图进入；不删除历史功能。

## 能力边界

- 选择的是本次期限内观察到的最高版本，不保证不可达的官方源没有更新；全部源旧或离线且没有有效快照时显示检查失败。
- 镜像不是密码学认证的发布者。文件名/版本绑定不等于字节完整性，不替代 SHA-256、精确字节大小、平台签名或系统安装器检查；相关下载器缺陷另批处理。
- 更新源设置按有效布尔值监听；同值的初始流事件不重建 feed，切换时退役旧 feed 并取消其请求。旧响应和排队启动弹窗不能发布到新模式；页面保留的旧来源快照明确标成上次结果。
- 不在本批修改共享 `FileDownloader`、通用 `raceFirst`、字体下载或 TV 外壳样式；不能据此宣称 #70 全部完成或 Sony 原机已修复。

## 回归与验收

- `update_feed_provider_test.dart`：真实设置流的切换、同值初始事件、退役请求、离线保留的来源标注、跨来源迟到页面/角标。使用原 API，可在旧源码上做行为回归。
- `update_feed_race_test.dart`：仅用原有公开 API 的行为回归，支持在旧源码上证明先旧后新、先坏后好和同版本构建竞争。
- `update_feed_snapshot_test.dart`：新快照接口的安全性、离线缓存、同版本错构建、空/坏历史、并发过期结果和全平台现有文件兼容。
- `version_page_test.dart`、`update_dialogs_test.dart`：旧/当前版本不提供升级、刷新与销毁隔离、元数据/文件不串代、下载入口拒绝错误身份和错误来源；历史下载、跳过和各平台原有交互继续回归。
- 全量门禁与 Sony/K90 现场结果分别记录，不混写为已经完成。
