# Y02.3 更新包字节完整性

接 Y02.2：保留更新源快照、版本/构建比较、升级资格和来源切换隔离，补齐安装包字节校验与下载终态。此项不代表 #70 的电视样式或原 Sony 设备已经验收。

## 根因与兼容

原下载器只用目标文件名识别 `.part`，跨镜像直接续写；任意非空分片加 HTTP 416 即视为成功；206 只检查起点，未检查终点/完整跨度；200 只拒绝短包，允许超长包及空的其他 2xx；替换时先删除已有目标。更新弹窗取前六个镜像，可能永远不尝试最后的 GitHub 原始地址。此外，关闭弹窗只发出取消信号，不代表旧文件操作已经结束：旧句柄的延迟写入可在再次打开同一目标后改写已经校验并重命名的新文件。现有文件名净化已覆盖路径分隔符，本项不把它描述为路径穿越缺陷。

3.x 的两个发布 JSON 位置、根列表/对象结构、原有字段和显示用 `size` 保留。新增可选发布 `build_number`、文件 `size_bytes`/`sha256`；旧读取器忽略新增字段，不因此获得校验能力。精确大小/构建必须是正整数且不超过 2^53−1，摘要必须为 64 位十六进制。显式损坏或不完整字段不能退回旧式未校验安装。

新客户端只把拥有有效精确大小及摘要的包交给应用内安装入口。旧历史仍可读、仍保留历史确认和明确浏览器下载动作，不静默安装缺少校验信息的包。发布端应先补全最终安装包元数据，再发布依赖它的新客户端。

## 下载契约

- `FileDownloader.download` 新增可选 `DownloadIntegrity`，绑定原始 URL（保留查询）、版本、构建、精确字节数和摘要；最快镜像只是传输地址。字体调用不必提供新参数，保持字体签名检查和目录回滚；无摘要时每个来源/调用重新下载，不凭文件名或跨站 ETag 续写。
- `.part.meta` 采用版本化身份并通过临时文件重命名写入。旧孤立分片、损坏/不匹配 sidecar、超长分片先重置。匹配完整分片必须重新流式计算全文件 SHA-256，才可不联网复用。
- 有效身份允许跨镜像续写，但最终校验包含已有前缀；不只校验新后缀。身份不是发布者认证。错误摘要会重置，每个去重来源至多一次干净重试；更新列表至多六个不同来源并预留原始地址，因此最多十二次实际下载请求（探测不计安装校验）。
- 下载器固定 `Accept-Encoding: identity`，不允许调用方覆盖 Range/表示头。只接受完整 200 或完整单段 206；206 的起点、终点、总长、跨度及 Content-Length 必须一致，拒绝多段、未知总长及尾随垃圾。200 忽略 Range 时从头写；超长/空包不能成功。416 一律不据此提升分片；完整合法分片已在发请求前校验，服务器无权把未完成文件变成成功。
- 同一 Dart isolate 内，不同下载器实例按规范化绝对目标路径排队；Windows 路径大小写保守折叠。所有重置、写入、校验、提交及等待中的恢复/清理结束后才释放目标；前项失败不传染后项，等待项取消也不能让第三项越过尚未结束的前项。不同目标可并行；不声称跨 isolate、跨进程或符号链接别名互斥。
- 精确字节数和全文件摘要都通过后，先在同目录保留已有目标副本，再进入最后重命名。失败时恢复旧目标；恢复本身失败则保留恢复副本并报告磁盘错误，不报告成功。没有跨平台崩溃原子性的保证。
- 流、等待、校验、进度回调及备份后均检查取消；进入最后的文件系统重命名是不可取消的提交边界。边界前取消不提升文件并保留匹配分片身份；已开始的重命名不可保证撤销。界面另行检查取消状态，不在取消后显示安装成功。提交后的 sidecar/备份清理失败不把已成功替换误报为未下载；残留 sidecar 不能绑定不存在的分片。

## 发布端工具

`tools/release/integrity_manifest.py` 提供离线 `generate`/`validate`。显式指定历史、版本指针、最终签名/打包产物目录、SHA256SUMS 和标签；生成只允许新输出文件，不覆盖现有 feed。校验所有提供的安装包名称、版本、构建、平台覆盖、URL 文件名、重复记录和摘要。目录、清单和 SHA256SUMS 的安装包集合必须一致，SHA256SUMS 本身不是安装包。

必须对最终实际上传字节计算，不用签名前/重打包前文件；Apple 产物也不能例外。工具不能发现未提供的远端资产，也不执行上传、发版或修改更新指针。授权发布时先验证上传字节，再发布完整历史，最后切换版本指针；这不使独立镜像原子同步，仍需 Y02.2 一致性保护。

## 安全边界

摘要来自同一份镜像元数据时，只证明字节与该元数据一致并检测损坏/错包，不能证明独立发布者真实性。能够同时替换元数据和安装包的人仍可提供匹配摘要。此项不建立签名更新框架，不跳过 APK、Windows、macOS、iOS 或操作系统签名检查。
