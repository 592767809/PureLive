# L01.4 内置列表初始化统一

- 状态以[登记表](../../../tasks.toml)为准。
- 来源：[issue #72](https://github.com/wzgrx/PureLive/issues/72)；保留 [issue #6](https://github.com/wzgrx/PureLive/issues/6) 已承诺的删除不复活语义。

## 根因与目标

`IptvSite.hotRooms` 在热门入口发现频道为空时调用 `IptvImporter.loadHotPlaylist`，而管理页的 `iptvOverviewProvider` 只读取数据库。全新安装直接进设置时没有触发同一初始化，访问热门后才出现列表。目标是从任意已有入口得到一致的默认列表状态，同时不把主动删除、备份恢复和网络失败混为“空库应该重建”。

## 方案

1. 共用内置列表导入入口，返回真实结果；并发调用共用在途操作。
2. 下载前保存内置列表快照，提交时在串行区核对快照和实时删除标记，旧下载不能覆盖恢复的新快照或让删掉的列表复活。
3. 管理页首次加载时只对“缺少内置列表且未主动删除”初始化，复用已有状态卡表达加载、失败和重试；导入器在捕获快照时再次确认缺失，已有/恢复的内置列表不重复下载。
4. 继续使用 `Settings.iptvHotRemoved`，不新增初始化开关；显式恢复仍由用户主动操作；若加入了删除前的旧下载，在旧结果失效且列表仍缺失时补发一次新下载，离开页面不取消已授权恢复。默认节目单流程不变。

## 边界

这是对现有小范围行为缺口的修正，不改管理页整体设计、节目单、播放策略或自定义源。原 3.x 的可访问默认内容保留，但不恢复其“删后又出现”的旧行为。测试只用假 HTTP 和隔离数据库，不访问真实直播平台。

验证见[任务书](brief.md)、[记录](record.md)、[原机清单](verify.md)。
