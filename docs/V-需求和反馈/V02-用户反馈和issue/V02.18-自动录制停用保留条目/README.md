# V02.18 关闭开播自动录不删除主播和任务，核验重启自动恢复设置

来源：[issue #19](https://github.com/wzgrx/PureLive/issues/19)。本轮用户要求全面分析评估并解决新增反馈。工作分支 `ai/V02.15`，基于 5.4.7 发布后的 `fb2bdb61e`。

## 根因与评估

setAutoRecord(false) 对 waitingLive 直接调用 removeTask，导致卡片、画质和弹幕配置一起删除；记录中的任务则只改 autoRecord，开关行为前后不一致。

## 本次方案

关闭时持久保存 autoRecord=false；等待中的任务停止轮询但保留任务和全部选择，正在录制的任务继续本场。只有删除操作移除条目。已有启动恢复设置和每任务选择本来会持久保存，不增加重复开关，不改变全局默认值；说明中明确如何开启重启自动恢复。

## 3.x 与参考

以现有 3.x 操作为基线，修复具体缺陷或补足已有功能的状态。参考本机 v3ref（当前上游 `6b9f6c318`）和 pure_live_TV；不复制上游架构，不修改版本和更新通道。

## 验证与边界

应用菜单回归要求同一任务仍在且开关为关，旧代码失败。另有两条内核用例验证重启后的任务身份、画质、弹幕与自动开关，以及停用任务不轮询、全局启动恢复关闭时不擅自开录。

所有“代码修复”均与“真实设备验收”和“已发布”分开记录。除 V02.20 中明确写出的斗鱼登录核验外，本轮未声称 Android TV、掌机、Windows 安装版或 Apple 设备已逐项验收。小范围交互补充沿用现有组件和布局，不重画整个页面；醒目留言会话范围已经用户确认，其他细节按 D-003 选择。
