# V02.20 斗鱼官方登录后无法播放的跨账号差异：真机核验并收集失败阶段

来源：[issue #15](https://github.com/wzgrx/PureLive/issues/15)。本轮用户要求全面分析评估并解决新增反馈。工作分支 `ai/V02.15`，基于 5.4.7 发布后的 `fb2bdb61e`。

## 根因与评估

尚未确认。两位反馈者分别在 Android 和 Windows 登录后失败；退出登录可以播放。不能仅凭“无法复现”认定反馈无效，也不能直接套用上游旧版 UA 问题。

## 本次方案

按用户单独授权，仅操作红米 v4dev 测试包完成官方短信登录。游客状态实际视频为蓝光4M；登录成功后冷启动同一房间为原画1080P60，另一个房间同样原画正常，账号页显示登录有效。此账号未复现失败，不改未经证实的鉴权逻辑；继续收集受影响用户的脱敏日志和错误阶段。

## 3.x 与参考

以现有 3.x 操作为基线，修复具体缺陷或补足已有功能的状态。参考本机 v3ref（当前上游 `6b9f6c318`）和 pure_live_TV；不复制上游架构，不修改版本和更新通道。

## 验证与边界

测试包版本 5.4.7+5111；普通 profile，正式包和数据未操作。验证码仅在内存中读取和使用；手机号、验证码、Cookie、设备地址均不进源码、样本或报告。测试后关闭本次直播并退出测试登录，恢复未设置状态，旋转仍为 0；临时登录截图已删除。

所有“代码修复”均与“真实设备验收”和“已发布”分开记录。除 V02.20 中明确写出的斗鱼登录核验外，本轮未声称 Android TV、掌机、Windows 安装版或 Apple 设备已逐项验收。小范围交互补充沿用现有组件和布局，不重画整个页面；醒目留言会话范围已经用户确认，其他细节按 D-003 选择。


## 2026-10-23 新反馈与诊断补齐

5.4.8 新日志含游客播放成功的耗时和镜像/连接警告，没有登录后房间详情、清晰度或地址解析失败的具体阶段。镜像连接警告不能直接当成斗鱼鉴权失败根因。仍未复现受影响账号差异，不改 Cookie、UA、鉴权与游客回退策略。

本轮 ai/V02.21 在 room_controller.dart 的 detail、qualities、urls 失败出口补 AppLog WARNING：平台、六位哈希房间、阶段和规范错误种类；不写原始异常文本、URL、响应、Cookie 或设备地址。此前仅 developer.log 不进入导出日志，这是确认的诊断缺口。新增三个失败阶段测试在改前失败、改后通过，并确认私密测试标记没有进入导出。

账号播放问题继续开放；需要受影响用户在候选构建复现后提供 playback-failure 行及发生时间，不能把日志补齐当成修复。旧真机核验仍只是旧版本和单个获授权账号的结果，本轮没有操作设备或登录账号。
