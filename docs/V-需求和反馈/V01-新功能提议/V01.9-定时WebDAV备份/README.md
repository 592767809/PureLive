# V01.9 应用运行时的定时 WebDAV 备份

- 编号、状态、档位、规模：以登记表为准，见[子分类页](../README.md)和 [STATUS.md](../../../STATUS.md)
- 类型：功能（新功能提议，有界面）
- 来源：用户 2026-10-24
- 相关：D-058；J04.2（逻辑）、A12.7（界面）；J04 WebDAV、A12.5 页面

## 目标

WebDAV 现在只有手动上传。用户希望应用运行时按间隔自动上传备份，上传成功后弹一个应用内通知。

用户确认的范围：

- 不做 Android 后台任务（不用 WorkManager），只在应用运行时检查；启动补跑一次，运行中按间隔检查，回到前台补跑。
- 只上传，不自动恢复。
- 成功后弹应用内通知；失败时本次运行第一次失败弹一次，之后只写日志。
- 新增设置跟随备份文件恢复。
- 远程目录默认在服务器根目录下的 `purelive` 文件夹，可自定义相对路径。
- 手动上传行为不变。

## 和 3.x 比

3.x 没有定时 WebDAV 备份。4.x 保留 3.x 的手动上传、文件名和配置键，只新增设置和自动上传。

## 方案

1. 设置：开关（默认关）、间隔（默认 24 小时，1..168）、内容（全部设置 / 仅关注，默认全部）、远程文件夹（默认 `purelive`）、保留份数（默认 7）、是否包含账号（默认否）。
2. 文件名：`purelive_auto_<时间>.txt`、`purelive_favorites_auto_<时间>.txt`；保留份数只清理这个格式，不动手动备份。
3. 上传：先逐层创建远程目录（MKCOL，最后 PROPFIND 确认），再导出并 PUT。
4. 调度：`AppStartup` 只在主窗口启动；启动、回前台和设置变化时检查；运行中每 15 分钟检查一次，按间隔和失败退避决定是否上传；不启动后台服务。
5. 通知：成功每次弹应用内通知；失败本次运行第一次弹一次原因；不自动恢复。

## 验证（做了以后）

- 自动测试：文件名和保留匹配、目录校验、到期和退避、上传和 meta、保留清理、设置界面、MKCOL、i18n。
- 真机/桌面：本机临时 WebDAV 上验证首次上传、目录创建、成功通知、手动上传不受影响、保留清理、失败通知和恢复补跑；Windows 第二窗口只上传一次。

## 留下的问题

- 应用被系统冻结或关闭时不会备份；这是用户选择的运行时方案。
- 坚果云、Nextcloud、Alist 的 MKCOL 细节仍需真机核对（S02.4）。
