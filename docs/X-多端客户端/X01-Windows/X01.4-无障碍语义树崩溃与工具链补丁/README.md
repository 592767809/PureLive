# X01.4 无障碍语义树崩溃与工具链补丁

## 根因和证据

首候选 b3f97af 的 Windows 原生正式包在开启 UI Automation 查询、主画面中键进入窗口内全屏后退出。应用没有 Dart 异常；WER 转储与匹配 PDB 显示 ui::AXNodeData::GetStringAttribute → AXPlatformNodeWin::get_accValue → memcpy 的失效节点读取。之前出现 Nodes left pending / not the new root 的 AXTree 更新失败。

[Flutter 193372](https://github.com/flutter/flutter/pull/193372) 于 2026-10-19 合并，提交 b304cf18b6864d141cf08e26a07898901cddb4b5。它避免向引擎序列化缺少 traversal parent 的 OverlayPortal 子树，父节点注册、脱离或改标识时同步更新关联节点。固定 3.47.7 基线尚未包含修复。[190357](https://github.com/flutter/flutter/issues/190357) 与 [193588](https://github.com/flutter/flutter/issues/193588) 提供机制线索；193588 是 macOS 报告，只作为失效节点后续查询的机制参考，不宣称修复其全部情形。190344、190903 未合并，不纳入本次补丁。

独立 SDK 副本仅加入该官方补丁，应用源码、原生引擎二进制、本地生成视频和无凭据数据库保持一致。官方语义回归修改前四项失败、修改后七项通过；应用保持无障碍开启，中键进入和退出窗口内全屏、返回首页、进入含两个 Material Slider 的设置页均正常，未再记录 AXTree 更新失败。完整转储和私有运行记录保存在本机 outputs/purelive-5.4.18，不提交真实用户数据。

## 方案与验收

tools/flutter_sdk 固定原 SDK revision、官方补丁 SHA-256 和修改前后两个文件哈希。显式应用时先核对整个输入，再写入；不支持的 SDK、额外改动或部分应用状态拒绝处理。门禁只检查补丁并运行官方七项回归，不静默修改共享 SDK。Windows、WSL 使用独立工具链副本，Apple 云构建在固定 SDK 安装后显式应用同一补丁。

最终源码重新执行 all/14；十包全部重建，原候选保留私有证据。Windows 最终包的中键、设置、导航和无障碍查询另行验证，不把诊断包当最终包验收；原 #47 窗口问题继续开放。


## 最终稳定工具链选择

2026-10-26重新核对官方发布索引，最新稳定版是2026-10-23发布的Flutter3.47.8（737ba8f885dc774b53b442759999a312c9461e4e）／Dart3.13.7。官方该revision的两个语义文件与3.47.7修改前哈希完全一致，仍不含193372；因此将发布基线改为3.47.8，再应用同一份已合并补丁。3.47.7的调用栈与红绿对照保留为诊断证据，不当成3.47.8最终包验收。尚在运行的3.47.7补丁版全量门禁已受控停止，日志和指纹保留，未计为通过；构建等待器先停止，未提交或推送该中间状态。最终门禁和十包会使用新稳定基线重新执行。
